# BUG-2026-025 设备菜单在小视口裁切

- 状态: 本地验证通过，待提交
- 发现与更新日期为 2026-11-08，Asia/Shanghai
- 任务分支为 `fix/p1-machine-menu-fit`

## 现象与影响

小窗口或较大的界面缩放会缩小逻辑视口。豆坊、发酵缸菜单的面板、关闭按钮和指南导航可能超出屏幕，妨碍查看状态和完成操作。

## 环境与前置条件

Windows x64，游戏 1.6.15 build 24356、SMAPI 4.4.0、Content Patcher 2.9.0、开发包 `0.1.0-alpha.2`。用专用 `XYSP1Menu` 副本运行 GameHarness 的 Memory 模式。回归在实际游戏程序集内临时设置逻辑 UI 视口。

## 复现步骤

1. 在 1000×680 逻辑视口打开设备菜单，并打开第二页指南。
2. 将逻辑视口改为 540×300，通知现有菜单窗口尺寸发生变化。
3. 旧构建返回面板范围 `X:-90 Y:-80 Width:720 Height:460`，超出视口。面板和全部可操作按钮应落在视口内。

## 根因分析

`MachineMenu` 以固定 720×460 尺寸创建面板，继承的窗口调整逻辑只移动面板原点。文字、按钮与原版关闭按钮各用固定偏移，视口缩小时缺少共同的缩放和重定位。既有点击检查假设按钮位于未缩放的固定偏移，未覆盖小视口。

## 解决方案

`MachineMenu` 用逻辑视口计算面板缩放和居中位置。绘制、文字和命中区域共享缩放，外侧预留空间给原版关闭按钮。尺寸回调、绘制和鼠标点击都能刷新布局。重排保留同一菜单的指南状态、请求与完成锁。

## 单元测试

`dotnet run --project tests/MachineCore/MachineCore.csproj -c Release` 通过 116 项，其中已有同菜单失败重试和成功锁检查。视口布局的回归需加载游戏 SDK，放在 `tests/GameHarness/ModEntry.cs` 的 `machine menu fits a narrow UI viewport and preserves its open session on resize`。旧版实机在面板越界断言失败。修复后复跑覆盖视口高度和宽度受限、恢复大尺寸、指南导航、关闭、缩放后开工和完成锁。

已有的 `full inventory collection retries in the same menu and locks after success` 补查满包拒绝后缩放。腾出一格后以原请求 ID 领取一次，检查原料、产品和状态。该补充断言在修复阶段加入。

## 验证结果

旧包实机 10 项通过后在新增用例失败，夹具恢复成功。新包的生产与夹具 Release 均为零警告、零错误。新进程的 Memory 回归 19 项通过，`Failure=null`、`Restored=true`。540×300 和 480×440 逻辑视口内的所有目标均可操作，扩大到 1000×680 恢复原尺寸。两个预期错误来自事务故障注入。

中文预览中，在指南第 2 页实际最大化再还原窗口，页码保持第 2 页。还原后用鼠标翻回第 1 页，再用关闭按钮回到游戏。两轮预览均已退出并禁用夹具，均为零次原生写盘，47 个存档文件哈希匹配基线。原报告、日志、审计及上一开发包归档于 `.local/p1-menu-fit`。

## 风险与回滚

改动限于菜单几何和显示。若布局引入新的可见问题，停止预览后换回归档的上一开发包。回退无需存档迁移。手柄和更多语言仍需独立覆盖。
