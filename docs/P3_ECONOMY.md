# P3 经济核算

核算基线为 `780eeda` 的全量 P2 清单，适用本轮固定 Windows Stardew Valley 1.6.15.24356、SMAPI 4.4.0、Content Patcher 2.9.0。配方、原料、售价和学习费取自 [内容清单](../data/catalog.json)。原版价格取自同版本 `Data/Objects` 与 `Data/Shops`，食用恢复和价格倍率按同版本原版方法计算。目标见[设计完成标准](DESIGN.md#9-完成标准与开发顺序)与 [P3 开发计划](DEVELOPMENT_PLAN.md#6-p3平衡兼容性验证与发布准备)。

## 口径

- 基础价以普通品质、标准利润率、无职业的单件直售价计。基础原料成本是把同一批输入直接卖出的机会成本。每批增值为产量乘以单价再减原料成本。每机器小时等于每批增值乘以 60 再除以配方分钟。行程、菜单停钟、收取操作、种植占地与并行设备单独考虑。
- 采购情景将可直接购买的输入换成柜台价。黄豆和大白菜按季外补货价，煤默认首年克林特价。仍需采集、种植、加工的输入按其普通直售价估值。厨房表的豆制品和调味料采用成品直售价，完整生产链另行以最初原料核算。
- `农耕人＋工匠` 是另一套出售情景。涉及 `Category=-75` 的黄豆、大白菜、小麦、蚕豆，以及耕种获得的辣椒，单价按 1.1 倍取整。自建设备和熏鱼机的本模组产品是 `Category=-26`，按 1.4 倍取整。两种倍率都用于重新核算输入机会成本和输出售价。厨房成品 `Category=-7` 不获工匠倍率。原版 `Object.getPriceAfterMultipliers` 有额外品质、来源和职业分支。
- 表中恢复为普通品质单份体力／生命。体力是 `ceil(Edibility × 2.5)`，生命是 `int(体力 × 0.45)`。原版 `Object.staminaRecoveredOnConsumption`、`Object.healthRecoveredOnConsumption` 处理品质及原版特例。这里只计算本模组食品，无齐氏调味料、增益或生命与体力上限截断。

## 复算方法

在仓库根目录运行以下 Python 代码，可从当前目录和固定原版参考值重算普通品质、采购情景与职业情景。设备每小时用输出总价减原料成本后乘 60、除以 `minutes`。脚本不读写存档。原版换版时先复核 `Data/Objects`、`Data/Shops` 以及 `ShopBuilder.GetBasePrice` 和 `Object.salePrice`，再更新固定参考值。

```python
import json
from fractions import Fraction
from math import ceil
from pathlib import Path

catalog = json.loads(Path("data/catalog.json").read_text(encoding="utf-8"))
items = {item["qualifiedId"]: item for item in catalog["items"]}
base = {id_: item["balance"]["price"] for id_, item in items.items()}
base.update({"(O)262": 25, "(O)260": 40, "-5": 50, "(O)423": 100, "(O)245": 50,
             "(O)247": 100, "(O)382": 15, "(O)388": 2, "(O)390": 2, "(O)334": 60})
retail = base.copy()
for id_, item in items.items():
    source = next((source for source in item["sources"] if source["kind"] == "shop"), None)
    if source is not None:
        retail[id_] = source["price"]
retail.update({"(O)423": 200, "(O)245": 100, "(O)247": 200, "(O)382": 150})
profession = base.copy()
for id_, item in items.items():
    multiplier = {-26: Fraction(7, 5), -75: Fraction(11, 10)}.get(item["category"], 1)
    profession[id_] = int(base[id_] * multiplier)
profession.update({"(O)262": 27, "(O)260": 44})

def inputs_at(recipe, prices):
    return sum(prices[entry["item"]] * entry["quantity"] for entry in recipe["inputs"])

for recipe in catalog["recipes"]:
    if recipe["implementation"] == "planned" or recipe["station"] == "crafting":
        continue
    output = recipe["output"]
    id_ = output["item"]
    item = items[id_]
    sales = output["quantity"] * base[id_]
    base_cost, retail_cost = inputs_at(recipe, base), inputs_at(recipe, retail)
    profession_delta = output["quantity"] * profession[id_] - inputs_at(recipe, profession)
    edible = item["balance"]["edibility"]
    energy = ceil(Fraction(5, 2) * edible) if edible >= 0 else None
    health = int(Fraction(45, 100) * energy) if energy is not None else None
    print(item["key"], recipe["minutes"], sales, base_cost, sales - base_cost,
          retail_cost, sales - retail_cost, profession_delta, (energy, health), recipe["unlock"].get("price"))
```

## 候选取舍与实测边界

当前数值保留到发布候选的实际职业与食用检查。豆坊核心配方基线增值接近，季外购料和长工时给自种保留价值。麻婆豆腐应先验证家庭长期经营时的出货收入和恢复，按完整原料链计利润。油菜暂按食用、赠礼和菜品选择评估。腊肉评价同时呈现购煤与自采煤结果。现阶段证据只支持这些优先检查，没有支持调整某个单价、工时或恢复量。

已完成的原生证据包括季节商店和两种作物、十条设备菜单批次、三台熏鱼机自然工时和全部 16 条菜谱购买与烹饪。香椿拌豆腐另有实际售出、食用和赠礼记录。表中职业和品质倍率、所有成品出货结算、不同个体赠礼偏好及长期利润是待核范围。`ExcludeFromShippingCollection` 控制出货收藏记录，实物可否出货及完成度影响仍按候选实测单列。见[来源实测](validation/P2-sources-2026-11-16.md)、[生产实测](validation/P2-production-2026-11-16.md)和[厨房赠礼实测](validation/P1-kitchen-gift-2026-11-05.md)。
