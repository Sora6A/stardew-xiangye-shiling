# 《乡野时令》——核心体验与范围冻结稿

方案版本：0.4（收敛版）  
日期：2026-09-22  
状态：方案设计；尚未编写模组或完成游戏内验证。  
本稿为公开仓库的范围基线。文中明确移出范围的内容不列入开发待办。

## 1. 核心体验

出门采野菜，在农场种黄豆和白菜，回家用少量设备加工，再做成能吃、能送、能出售的中式食物。

保留时令采集、豆制品选择、酿酱腌菜和烟熏风味。工序由设备内部完成，玩家的主要选择是“这批原料做什么”，无需在多台单用途机器间倒料。

范围规则：

- 新增设备只有豆坊、发酵缸两种；烟熏扩展原版熏鱼机，油炸、卷制和卤制使用厨房配方。
- 保留本稿列出的核心品种；用途相近的外围产品移出本期，不再继续增加食品分支。
- 每个保留物品必须有可用的获取来源，以及明确的食用、烹饪或进一步加工去向。出售不能是全部原料的唯一用途。
- 饮品、料理和熟食本身可以作为终点，不为它们再造一道菜来凑用途。
- 同批投入默认只需等待一次并取货；浸泡、煮浆、凝固、压制、制曲、腌肉等在配方内抽象。
- 盐水、凝固剂、菌种等作为工艺背景，不新增对应背包物品、生产工具或管理系统。原版已有的糖、油等仍可作为显式原料。

“中国特色”由物品、美术、风味搭配和作坊布置体现。

## 2. 本期物品范围

| 类别 | 保留内容 | 来源 |
|---|---|---|
| 野外采集，4 种 | 竹笋、野葱、香椿、艾草 | 春季原版地图的采集点 |
| 种植作物，2 种 | 黄豆、大白菜 | 皮埃尔出售种子 |
| 商店食材，2 种 | 猪肉、蚕豆 | 格斯出售原料；不增加养殖或蚕豆种植系统 |
| 基础豆制品，6 种 | 豆浆、豆花、豆腐、油豆皮、千张、豆干 | 豆坊，以黄豆为主要原料选择配方 |
| 厨房豆制熟食，3 种 | 素鸡、油豆腐、兰花干 | 厨房配方 |
| 发酵品，4 种 | 酱油、黄豆酱、川式豆瓣、酸菜 | 发酵缸 |
| 烟熏品，2 种 | 腊肉、熏豆干 | 扩展原版熏鱼机配方 |
| 配套料理 | 见第 5 节，仅用于完成上述物品的用途 | 原版厨房 |

以上为 8 种新原料、15 种加工品；配套料理另列。原版小麦、辣椒、鸡蛋、大米、糖、油和机器耗材等直接复用。

命名与来源约定：

- “油豆皮”专指揭膜类产品，“千张”专指凝固后薄层压制产品，避免同名。
- “豆花”为可食用的原味成品，不强制作为豆腐生产的背包中间物。
- “酸菜”在本期固定为大白菜制成的酸白菜，物品说明写清原料。
- “川式豆瓣”使用蚕豆和辣椒，黄豆酱使用黄豆，不把两条路线混为同一种豆。
- 原版猪产松露，猪肉是本模组商店食材；不假设原版养猪能够取肉。
- 本期是春季采集加农场加工的完整版本，四季野外内容不再作为交付承诺。

## 3. 两种新设备及原版设施复用

| 设施 | 能做什么 | 玩家操作 |
|---|---|---|
| 新增：豆坊 | 豆浆、豆花、豆腐、油豆皮、千张、豆干 | 选已解锁配方，投入黄豆，等待后整批取货 |
| 新增：发酵缸 | 酱油、黄豆酱、川式豆瓣、酸菜 | 选配方，投入所需食材，等待发酵完成 |
| 复用：原版熏鱼机 | 新增猪肉→腊肉、豆干→熏豆干 | 原版操作为主；腌制等准备步骤包含在新配方内 |
| 复用：原版厨房 | 素鸡、油豆腐、兰花干，以及第 5 节料理 | 学配方后按原版烹饪方式消耗材料 |

豆坊表现为一处带石磨、灶口和压板的紧凑设备。发酵缸表现为陶缸。实际占地、精灵尺寸以原版可放置设备规格及实机效果为准。

烟熏配方保留原有鱼类加工规则。新增配方的耗材遵循原版机器的交互约束，在实现时统一验证；不额外造一套木柴或燃料物品。

删除独立的磨浆台、凝固缸、压制台、模具物品、揭皮锅、油炸锅、卤锅、晾晒架、盐田，以及专用中式熏炉。酱缸和腌菜坛合并为发酵缸。玩家无需修建这些工具才能生产保留的食品。

## 4. 加工配方与用途闭环

下表是简化游戏配方，数量、批量、售价和时间统一在原型中调整；不代表现实制作教程。

| 产品 | 获取或加工输入 | 必须具备的用途 |
|---|---|---|
| 豆浆 | 黄豆→豆坊 | 直接饮用，少量体力恢复 |
| 豆花 | 黄豆→豆坊，凝固过程内部完成 | 直接食用、送礼 |
| 豆腐 | 黄豆→豆坊 | 香椿拌豆腐、酸菜炖豆腐、麻婆豆腐、油豆腐 |
| 油豆皮 | 黄豆→豆坊，揭膜过程内部完成 | 豆皮汤 |
| 千张 | 黄豆→豆坊，薄层压制内部完成 | 千张肉卷、素鸡 |
| 豆干 | 黄豆→豆坊 | 酱香豆干、兰花干、熏豆干 |
| 素鸡 | 千张＋酱油＋油→厨房，卷制与烹调合并 | 食用、送礼；作为熟食终点 |
| 油豆腐 | 豆腐＋油→厨房 | 食用、送礼；作为熟食终点 |
| 兰花干 | 豆干＋酱油＋油→厨房，切花炸卤合并 | 食用、送礼；作为熟食终点 |
| 酱油 | 黄豆＋小麦→发酵缸 | 油焖笋、素鸡、兰花干、千张肉卷 |
| 黄豆酱 | 黄豆→发酵缸 | 酱香豆干 |
| 川式豆瓣 | 蚕豆＋辣椒→发酵缸 | 麻婆豆腐 |
| 酸菜 | 大白菜→发酵缸 | 酸菜炖豆腐 |
| 腊肉 | 猪肉→熏鱼机扩展配方 | 竹笋炒腊肉 |
| 熏豆干 | 豆干→熏鱼机扩展配方 | 野葱炒熏干 |

设备可以提供不同终点，但不给玩家强制串接“豆浆→豆花→豆腐→豆干”的四次操作。现实工艺用于配方说明、耗时与美术表现。

酱油等调味品按小份批量产出，一份对应一次菜谱消耗。豆浆与原料豆腐也按合理份数出货，不用瓶内耐久或逐口消耗系统。

## 6. 获取、解锁与节奏

- 四种野菜都用原版风格的地面拾取，首批只投放森林、山区、巴士站等经过实机检查的白名单地图。香椿、竹笋的物品表现按原版采集抽象处理。
- 野葱与原版大葱使用独立 ID、图标和配方，保留原版大葱及其规则。
- 暂定黄豆夏秋种植、大白菜秋季种植；这是游戏设定，生长天数待平衡。皮埃尔提供种子和有限数量的季外原料补货。
- 猪肉、蚕豆为常规可购原料，不依赖随机旅行商店。
- 设备图纸集中由罗宾出售，食品配方集中由格斯出售。具体价格与进度门槛以后只调整数值，不增加任务链。
- 豆坊以短周期批量生产为主，发酵缸以较长周期批量生产为主。生产完成后留在机器里等待领取，玩家不必每天照料。
- 原料与成品沿用通常的储存体验；不增加腐败、天气损毁、菌种养护或瓶内剩余次数系统。

所有机器、配方及必要原料必须能在明确的游戏阶段取得。实际界面能看到投入、批量产出及预计完成时间，避免玩家靠猜试配方。

以上为明确的排除项，不是后续版本承诺。本期开发不自动扩展这一清单。

## 8. 实现边界

目标平台暂按桌面版星露谷 1.6；具体操作系统、游戏版本和地图模组待实际开发前确认。

物品、作物、图像、本地化、商店和菜谱优先通过 Content Patcher 数据补丁实现。原生数据可以表达的熏制规则按原版机器追加，不替换整张机器表。

豆坊与发酵缸需要同一种原料选择不同配方，且部分配方含多个输入。因此将“共享的配方选择与批量投料交互”列为最小代码模块的实现验证点，不假定普通 Content Patcher 内容包天然具备此界面。仅为这两种设备提供同一套简单菜单；不引入模具道具、原料包、每道配方独立机器或复杂科技面板。

实际原型应先验证多原料一次扣除、批量产出、机器工作状态和存档；需要代码时使用小型 SMAPI 模块。配方选择不是免费换产物：每个配方都明确消耗、产量和计时，工作中禁止变更。

保留的工程约束：

- 全部内容使用稳定的独立 ID；中英文文案独立于内部名称。
- 采集新增条目会与原版物品竞争机会，必须检查原版关键采集物可获得性；不承诺每图每天固定产量。
- 处理旧档加载、多人主机权威、配方学习状态、机器移动与保存；不要由各客户端重复扣料或重复产出。
- 确认物品分类、职业加成、收集页面和完成度影响；未验证的地图扩展与自动化模组不宣称兼容。
- 更新保持 ID 稳定；卸载前处理模组物品并备份。新图标遵循原版像素比例并检查实际显示。

## 9. 完成标准与开发顺序

一版交付目标是本稿的完整范围，分三步实现，不再增加扩展版本承诺：

1. 验证公共机制：先打通黄豆→豆腐→香椿拌豆腐，以及黄豆＋小麦→酱油，确认配方选择、耗材、等待与存读档可行。
2. 填齐内容：补上本稿明确保留的物品、两种作物、四种采集物、设备配方和 13 道料理；每一项检查“能获得、能加工、能使用”。
3. 平衡与打磨：核查收入、耗时、体力恢复、原版生成影响、图标、旧档和多人行为，再打包。

验收要点：

- 不存在只能靠控制台获得的正式物品，也不存在只有名字、没有使用去向的原料。
- 原料不足、背包满、机器忙等情况下不重复扣料或丢失产品。
- 豆坊有 6 个有效产品方向，发酵缸有 4 个有效产品方向；全流程无需旧方案中的专用工具。
- 厨房 13 道配套料理和 3 种豆制熟食的原料都来自本期范围或原版。
- 酱油、黄豆酱、豆瓣的批量产出和原料成本经过核算；原料直接出售、做菜和深加工均有合理用途。
- 新档与旧档副本、至少双人联机、季节切换和存读档验证通过。
- UI 能表达正在制作的配方、所需材料和结果；完成后领取明确，不能切换配方复制产品。

当前仅完成设计，上述游戏内验证尚未执行。具体任务与验收顺序见 [开发计划](DEVELOPMENT_PLAN.md)。
