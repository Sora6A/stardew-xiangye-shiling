## 回归内容与通过条件

入口 [PlacementScenarios](../../tests/GameHarness/PlacementScenarios.cs) 的两设备用例对 Processing、Ready、Corrupt、Idle 同 ID 占用格直接调用 `placementAction`，必须返回 false 且原设备引用/原 JSON、所有背包槽和携带物元数据不变。这是补丁组件边界回归，故意绕过 Utility 鼠标预检，不声称普通鼠标触发过覆盖。根因和修复见 [BUG-009](../bugfix/BUG-2026-009-occupied-placement.md)。

[ToolRemovalScenarios](../../tests/GameHarness/ToolRemovalScenarios.cs) 各设备一项，必须完整走过：

1. 对加工、待领取及损坏状态调用实际 `Pickaxe.DoFunction`，目标引用/JSON/库存和掉落实体集合不变。
2. 空闲设备经原生镐调用移除，地图空出且出现且仅出现一个真实、单 chunk、单设备 Debris，背包尚未取得设备。
3. 按正常帧长驱动该实体的 `Debris.updateChunks`，由其自行磁吸和 collect；仅完成后从位置集合移除，不直接调用 collect、不修改 chunk、不更新测试前其他 Debris。实际 payload 入背包一份。
4. 用实际背包 carrier 调用 `Utility.tryToPlaceItem`；同时核对地图新引用和 carrier 真实消耗，不能把 Utility 的 true 单独视为放置成功。
5. 新设备空闲、revision=0、新 instance ID；旧请求在有效范围且不使用工具的条件下拒绝、不改两侧；随后 fresh request 完整扣料并开始正确配方。

原生工具即使未移除设备仍可能按游戏规则消耗体力；保护断言针对机器/批次/库存/掉落，测试后恢复体力。工具用例临时隔离随机源和 HUD 列表；finally 恢复玩家状态、原库存引用数量、原格对象/元数据、菜单、时钟、随机源、统计和原掉落实体，并执行恢复断言。不会清空整个 debris 集合或移走家具。选址失败属于 [BUG-010](../bugfix/BUG-2026-010-tool-fixture-placement.md) 夹具问题，生产碰撞规则不放宽。

最终 `ToolFixtures` 两设备均记录原请求格 `(10,9)`，命中 `(F)2048` 床；动态设备格 `(8,7)`、站立格 `(7,7)`，NativePrecheck=true，且实际拾取后的 carrier 再次预检并完整放置通过。配合原失败与全碰撞检查源码，确认原候选的家具碰撞；距离按 X/Y 分别判断，不用曼哈顿距离归因。
