# P1 两设备自然工时 · 2026-11-08

本轮补上生产设备的自然计时验证。以当前开发包加载 `XYSP1Menu` 专用副本，在同一个早上开工并观察游戏时钟。此前的[世界操作链](P1-world-ui-2026-11-06.md)用准备时刻验证真实世界交互，本轮单独补自然经过的工时。

## 环境与范围

- Windows，游戏 1.6.15 build 24356、SMAPI 4.4.0、Content Patcher 2.9.0，中文单人。
- 隔离测试进程从原版标题页加载专用档，普通 `XYSP1Walk` 会话另在原进程。生产 DLL 来自当前 ZIP，未改规则、存档格式或生产包。
- [NaturalClock 夹具](../../tests/GameHarness/NaturalClockScenario.cs)准备两台设备与临时库存，开工和领取调用生产 `MachineService`。等待期间游戏窗口保持激活、菜单关闭。夹具只读取 `TimeChanged`，没有时钟赋值、推进调用或控制台命令。
- 保存会使本场景失败。夹具完成时恢复原背包引用并移除临时设备；不还原自然经过的时间。专用档退出时另查磁盘与原生日志。

## 实测结果

06:00 同时开工，扣除黄豆 6、小麦 2。原版时钟连续产生 24 次十分钟变化，至 10:00 经过现实约 175 秒。每次核对设备仍在原格，待领取前批次原值保持，成品不会提前进入背包。

| 原版时刻 | 豆坊 | 发酵缸 |
| --- | --- | --- |
| 07:50 | 提前领取被拒绝，批次与库存不变 | 加工中 |
| 08:00 | 整批领取豆腐 2，之后再领被拒绝 | 加工中 |
| 09:50 | 空闲 | 提前领取被拒绝，批次与库存不变 |
| 10:00 | 空闲 | 整批领取酱油 4，之后再领被拒绝 |

同一进程五项断言全部通过，报告为 `Completed=true`、`Restored=true`、`Failure=null`、`SavingObserved=false`。独立测试进程已从窗口退出并禁用夹具。原生日志确认加载一次、保存零次、错误零条，47 个存档文件哈希全部一致。普通会话和原 Mods 未被替换，生产 ZIP 十个文件和部署内容一致。

原报告、日志和 `audit.json` 位于 `.local/p1-natural-clock/native`。报告 SHA-256 为 `27B3C6527240B268CC531A3F38B0FE3A238CE500A9DC0B32E056A37895BF5E5B`，生产 DLL SHA-256 为 `169834E671F59DFB11BF409632CC74752CB7A34AAA81C7CC332625F93634EBA4`。

## 复跑

运行 `. ./tools/enter-dev.ps1` 后，以本机游戏与 SMAPI 引用执行 `dotnet build tests/GameHarness/GameHarness.csproj -c Release`。构建结果为零警告、零错误。按[夹具说明](../../tests/GameHarness/README.md#naturalclock两设备自然工时)在新隔离 Mods 中部署同一生产包和夹具，明确绑定专用档。开始前归档存档哈希；标题加载后保持无菜单，等待最终 `natural-clock-result.json`。测试结束关闭该进程，禁用夹具，再比对存档哈希和原生日志。

本场景不代替普通单人链。三店自然营业时步行采购、实际制作/放置、手工菜单领取和厨房串联仍按[普通流程记录](P1-ordinary-play-2026-11-07.md)单独完成。
